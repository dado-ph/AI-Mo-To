# Philosophical acceptance

AI-Mo-To succeeds when an ordinary need can become useful local structure
without making the person pretend to be a software architect. The proof is an
installed-product role-play, not a source-tree demonstration.

The canonical procedure and evidence contract live in
`scripts/acceptance/README.md`. A valid run demonstrates:

- outcome before ontology: the initial person message contains no technical
  design;
- conversation becomes structure: the installed workspace contains usable
  records, views, and actions;
- trust through visibility: planning leaves the revision unchanged and the
  exact reviewed digest requires explicit human approval;
- earned complexity: Files and Tasks are useful before Habit Tracker is added;
- ownership: provenance, permissions, revisions, and recovery are inspectable;
- replaceable intelligence: the transcript shows discovery through the public
  installed CLI, not repository knowledge or a private model integration.

A coached, auto-approved, source-backed, or evidence-edited run is a failure.
That failure starts another implementation and validation wave; it is not
waived as a testing limitation.
