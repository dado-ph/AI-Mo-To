# Philosophical acceptance

AI-Mo-To succeeds when an ordinary-language need becomes a useful local application without asking the person to design its architecture.

The installed-product role-play must prove:

- the initial message contains only the desired outcome;
- `request` returns the canonical workspace root and implementation context;
- `request` creates no version;
- an external coding agent implements a usable UI and connected behavior directly in that root;
- the first agent turn ends with verified working files and a request for permission to save them;
- only a later explicit human approval permits `version create`;
- the created version captures workspace files, and restore recovers those bytes as a new version while retaining history;
- the packaged desktop opens the same workspace and exposes its current version and history;
- the agent uses the installed CLI and never relies on private source-tree knowledge.

The evidence contract and commands live in [the acceptance harness guide](../scripts/acceptance/README.md). Coached, auto-approved, source-backed, or edited evidence is a failure.
