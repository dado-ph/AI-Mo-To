# Philosophical acceptance

AI-Mo-To succeeds when an arbitrary ordinary-language need can become a useful
local application without making the person pretend to be a software
architect. The proof is an installed-product role-play, not a source-tree
demonstration and not a collection of hard-coded example applications.

The Foundry is guidance for the external coding agent: it teaches reasoning,
the default stack, UI/UX, accessibility, safety and AI-Mo-To integration. It
does not define the complete universe of applications. The agent creates the
application's source code in an isolated AI-Mo-To-managed repository, and the
harness validates and proposes that generated artifact for explicit human
approval.

The canonical procedure and evidence contract live in
`scripts/acceptance/README.md`. A valid run demonstrates:

- outcome before ontology: the initial person message contains no technical
  design;
- conversation becomes software: the generated application repository contains
  a usable implementation, tests, views, and actions;
- trust through visibility: planning leaves the revision unchanged and the
  exact reviewed digest requires explicit human approval;
- earned complexity: Files and Tasks are useful before Habit Tracker is added;
- ownership: provenance, permissions, revisions, and recovery are inspectable;
- replaceable intelligence: the transcript shows an external coding agent
  working through the public installed CLI and Foundry guidance, not private
  repository knowledge or a purpose-specific generator.

A coached, auto-approved, source-backed, or evidence-edited run is a failure.
That failure starts another implementation and validation wave; it is not
waived as a testing limitation.
